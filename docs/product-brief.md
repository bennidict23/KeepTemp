# KeepTemp 产品初心

## 用户描述的起点

用户观察到：一些人共用 GPT、Claude 等 AI 账号，对话历史混在同一个平台账号里，工作内容、私人问题和思考过程容易被其他账号使用者翻看。为了减少普通历史中的暴露，他们会选择 Temporary / Incognito Chat。

由此出现一个矛盾：不希望对话留在共享历史，却希望自己还能找回、继续。关页、误操作、刷新、网络或浏览器故障，可能让一段已经投入很多轮思考的临时对话变得无法接续。

这是用户提供的需求假设和产品起源，不是经过市场调查的合购人数、使用频率或付费意愿结论。

## 核心任务

> 我希望对话不进入平台的普通聊天历史，同时在自己的设备上可靠保留文字，关闭页面后还能找回并继续；整个保存过程不需要我逐轮复制、整理或操作。

一句话：**平台里保持临时，本机上可以接续。**

目标体验：开启一次 → 在原网页照常聊 → 自动本地保存 → 随时找回 → 一次复制完整历史与接续提示词 → 在新临时聊天粘贴发送，接着聊。

用户所说的 **prompt 是交给新会话 AI 的接续提示词**，用于让模型承接已有目标、事实、约束、结论、偏好和未完成请求；不指开发者的项目指导文档。用户无需自己编写提示词，也无需重新总结背景。提示词由本机固定模板与原始历史一起打包，不调用 AI 摘要，不上传，不自动发送。具体实现见 `src/recovery.ts`。

“接续”不等于恢复原服务端 session：当前只恢复角色与文字。Saved 只证明当次持久化成功，不能保证未生成、未挂载或未提交的内容已经备份。

## 产品取舍

你在维护 KeepTemp，一个帮助用户可靠保存和接续临时 AI 对话的本地优先浏览器扩展。

用户选择临时聊天，是希望避免对话进入平台普通历史；但他们并不总想把自己这段思考永久丢掉。KeepTemp 帮助他们同时保留临时聊天的使用习惯和自己找回文字的能力。

每次改动前，先判断它是否直接改善“自动保存、可靠找回、方便接续”中的至少一项。

- 自动保存是核心。不能把逐轮复制粘贴、整理角色或导入文件当成主流程，也不能把这种替代方案称为已完成核心需求。
- 保留原聊天习惯。授权后照常在平台网页聊天，不另造客户端，不要求注册、API Key 或后台服务。
- 可靠性比功能数量重要。消息不重复，会话不串，流式回复持续更新；写入失败必须真实可见，不能虚报 Saved。已适配平台的临时自动捕获在模式不确定时不捕获。通用模式的例外见下文，必须用户逐会话主动确认。
- 界面清爽。日常只需小状态标记、会话列表、搜索、阅读和接续；导出、暂停、排除、删除作为必要的数据控制。开发测试、诊断和模拟能力不出现在产品主流程。
- 本地优先。不上传、不接分析 SDK、不做云同步、账号系统、AI 摘要、Embedding 或复杂分类。
- 隐私承诺准确。平台普通历史、本机记录和平台端保留是不同的事情；共享账号并不因此获得真正的用户权限隔离。同一浏览器配置下的记录也不对其他本机使用者隔离。当前数据库未做应用层加密，不是密码保险库。
- 不承诺恢复原平台会话、附件、工具状态、隐藏状态或未观察过的历史。未提交尾部不作不会丢失的保证。
- 用户于 2026-11-02 将范围明确扩展到 ChatGPT、Claude、Grok、Gemini，并要求跨平台接续。新增捕获适配为实验支持，合成测试不能替代真实网页验收。
- 来源平台只显示在会话库与导出记录中。用户确认接续提示词保持平台中立，不要求新模型扮演原模型。
- 不读取用户私人聊天用于开发；回归验证使用独立浏览器和合成内容。测试通过与真实页面验收分别报告。

如果一个功能只能让插件看起来更完整，却没有让用户更省心地保住自己的临时对话，就先不做。

## 需求判断与验证

工程与产品判断：这是明确、可解释的用户痛点，尤其在用户已经用临时聊天、曾经丢失有价值的长对话时。它不限于共享账号，独立账号使用者也可能有相同需求。

尚未证明：高频用户规模、安装权限接受程度、与既有工具的差异是否足够、持续使用率、付费意愿。不用“很多人合购”替代市场验证。

优先找 5–10 位已有临时聊天习惯的用户，让他们讲最近一次真实丢失的对话，再观察是否愿意安装并持续使用。只统计自愿提供的反馈，不接入遥测或上传聊天。

## 通用保存的明确范围（2026-11-02）

用户要求保存优先，尝试通用提取器，以 DeepSeek 验证。用户随后明确选择：“想，也能保存，但明确提醒网站里的历史仍然存在”。因此允许普通或模式未知的网页对话在预览、核对角色和正文、明确确认后保存。本地副本不使网页变成临时聊天，不隐藏或删除网站历史。原四家临时自动捕获继续严格识别。

通用模式以一次确认覆盖当前会话后续增量，不逐轮打扰；会话／路由变更必须重新确认。新网站只通过工具栏 activeTab 预览，确认时申请该 HTTPS origin 的可选权限。不默认获得全站权限。没有稳定消息／会话身份或角色冲突时拒绝保存，不能用位置交替或正文哈希冒充可靠身份。DeepSeek 只做实验性 DOM 适配，不使用任何私有 API 或凭据访问。

0.5.1 统一入口修正：上述主动确认规则也适用于已经有专用适配器的四家网站，不能在进入预览前被旧临时模式检查拦住。已知平台保留原生会话键和来源标签；已主动批准的记录后来被自动识别为临时，也不得新建重复会话、抹去主动模式标记或扩大授权。


## 0.6.0 用户明确收敛交互

用户明确取消保存前预览、逐次核对和二次确认，要求直接点记录。用户自己选择网站是否临时，插件不在主动保存时以模式未知拦截。首次说明和隐私设置保留本地副本边界，日常保存／阅读不重复展示长提醒。每段新通用会话一次点击，之后自动增量更新。

重复点记录必须合并当前页面的新内容；删除阻止自动复活，用户主动再次点记录则允许重新保存页面现有内容，不能谎报成功。用户要求自行模拟 QA，重点测试各种常见状态组合；不能让用户承担基础回归工作，也不能将合成测试当成真实账号兼容保证。

界面只使用黑／白与中性灰，明暗切换一个按钮并记住选择。保存按钮为主要操作，打开平台只是辅助入口；不堆功能或装饰。
