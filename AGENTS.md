# Project guidance

- Primary motivation: people sharing an AI subscription may not want co-users to see their questions in the common history. Temporary/incognito chats address that history concern but make useful conversations hard to retain. Lead product copy with this privacy-versus-retention tension; accidental closure and convenience are secondary benefits. Never imply the extension itself isolates a shared account.
- Purpose: let people keep using temporary chat while retaining a personal local text copy, finding it later, and continuing with one copied transcript plus continuation prompt. Keep the existing chat website as the main workflow.
- Keep the product small: capture, storage, search/read, context copy, export, rename/delete and pause controls. No cloud, accounts, telemetry, AI summaries, developer screens or repeated confirmation flows.
- After first-use consent, one explicit Record click may save ordinary or unknown-mode conversations too. Automatic capture without that click still requires confirmed temporary mode. A new generic conversation needs its own explicit grant.
- Never bypass pause/exclusion or storage failures. Show Saved only after commit; the record action must also verify the stored row. Repeated recording updates the same conversation. Deletion blocks automatic resurrection; an explicit re-record may save only currently readable content.
- Preserve the existing IndexedDB format and stored data. Keep adapters independent from storage and recovery. Unknown message roles or unstable identities must fail conservatively.
- Continuation means complete role-labelled text plus the fixed, platform-neutral continuation prompt. Never silently summarize or truncate. Copy only writes the clipboard. Only an explicit Continue action may paste/send in the current ChatGPT tab. Return directly to the same live conversation without resending context. Otherwise use an empty temporary composer, reusing capture mode evidence (explicit off overrides URL), and recheck consent/source record. Preserve committed current conversation content before any same-tab navigation; never discard drafts or interrupt streaming. Never open another tab for Continue. Never retry a send automatically. Source labels belong in the library and exports.
- Keep the UI minimal and monochrome, with a persistent light/dark toggle. Privacy boundaries belong in first-use information and settings.
- Use synthetic data and isolated browser profiles. Never read private conversations or include real chat text in logs, fixtures or screenshots. Synthetic DOM tests do not establish live-platform compatibility.
- Verify streaming, repeated recording, deletion/re-recording, refresh, tabs, virtual windows, copy fidelity and storage failures. Follow `docs/development.md`.
- State privacy and platform limits honestly: local data is not an encrypted vault, local copies do not hide website history, and continuation does not restore server sessions, attachments or tools. See `PRIVACY.md` and `docs/feasibility.md`.
